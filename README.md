# itmo-document-verification-service

**ВериДок** — локальный сервис проверки достоверности корпоративных документов. Практика ИТМО, 1 курс, 2 семестр (MVP).

## 1. Что это

ВериДок принимает проверяемый документ (PDF/DOCX/PPTX) и набор доверенных источников, извлекает из документа отдельные утверждения (числа, даты, имена, факты) и для каждого выносит вердикт: подтверждено источниками (`supported`), опровергнуто (`contradicted`), не найдено (`not_found`) или противоречит другому утверждению того же документа (`internal_conflict`). Каждая находка несёт ссылку на местоположение в документе (страница/слайд/абзац). Всё работает локально, без облачных API; интерфейс и документы — на русском. Все вызовы LLM выполняются при `temperature=0.0` для воспроизводимости.

**В scope:** парсинг PDF/DOCX/PPTX; извлечение атомарных утверждений через LLM; индексация источников в Qdrant и поиск по эмбеддингам; верификация по найденным фрагментам; проверка внутренней согласованности; отчёт в Streamlit и CLI.

**Вне scope:** облачные/внешние LLM-API; OCR сканов и изображений; обучение/дообучение моделей; аутентификация, многопользовательский режим, постоянное хранилище отчётов; форматы, кроме PDF/DOCX/PPTX.

## 2. Архитектура

Поток данных: источники индексируются в Qdrant; проверяемый документ проходит конвейер parse → extract → retrieve → verify; параллельно проверяется внутренняя согласованность; результат собирается в отчёт и отображается в Streamlit (или в консоли через CLI).

```
  ДОВЕРЕННЫЕ ИСТОЧНИКИ                       ПРОВЕРЯЕМЫЙ ДОКУМЕНТ
  (pdf / docx / pptx)                        (pdf / docx / pptx)
          │                                          │
          ▼                                          ▼
       parse                                       parse
   (PyMuPDF4LLM /                              (PyMuPDF4LLM /
    python-docx /                               python-docx /
    python-pptx)                                python-pptx)
          │                                          │
          ▼                                          ▼
    чанкинг + эмбеддинг                          extract
   (sentence-transformers)                  (LLM → утверждения:
          │                                  number/date/name/statement,
          ▼                                  каждое с location)
   ┌──────────────┐                               │
   │    QDRANT    │◀───── retrieve (top_k) ───────┤
   │ (коллекция   │       embed_query(claim)      │
   │  векторов)   │──────► evidence ──────────────┤
   └──────────────┘                               ▼
                                                verify
                                            (LLM по claim+evidence →
                                             supported / contradicted /
                                             not_found)
                                                  │
                            consistency           │
                       (LLM по всем claims ───────┤
                        → internal_conflict)       │
                                                  ▼
                                               Report
                                       (findings + stats + время)
                                                  │
                                ┌─────────────────┴─────────────────┐
                                ▼                                   ▼
                         streamlit run app.py            python -m veridoc.pipeline
                         (таблица + раскраска)            (таблица в консоли)
```

Если источники не предоставлены, все утверждения помечаются `not_found`, но проверка внутренней согласованности всё равно выполняется.

## 3. Стек

- **LLM:** `Qwen3.6-35B-A3B` по OpenAI-совместимому HTTP. Эндпойнт и имя модели задаются переменными `LLM_BASE_URL` и `LLM_MODEL`; обращение идёт через `openai` SDK.
- **Эмбеддер:** `Qwen/Qwen3-Embedding-8B` через `sentence-transformers`, устройство `mps` (`EMBED_DEVICE=mps`). Размерность вектора — `EMBED_DIM=4096`.
- **Векторное хранилище:** Qdrant — в режиме сервера (docker) или embedded (on-disk).
- **Парсинг:** PyMuPDF4LLM (PDF; `import pymupdf` / `fitz`), `python-docx` (DOCX), `python-pptx` (PPTX).
- **UI:** Streamlit.
- **Конфигурация:** `pydantic-settings` (см. `config.py`, читает `.env`).

## 4. Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # при необходимости отредактируйте значения
```

### Подъём LLM

Нужен любой локальный OpenAI-совместимый раннер, отдающий модель Qwen3.6 (например, `mlx-vlm server` или Ollama с MLX-тегом Qwen3.6). Укажите его адрес в `.env`:

```bash
LLM_BASE_URL=http://localhost:8080/v1
LLM_MODEL=Qwen3.6-35B-A3B
```

Локальные серверы обычно игнорируют ключ, но `openai` SDK требует непустое значение — поэтому `LLM_API_KEY=not-needed`.

### Qdrant

Вариант 1 — сервер в Docker:

```bash
docker run -p 6333:6333 qdrant/qdrant
```

и в `.env` оставьте `QDRANT_URL=http://localhost:6333`.

Вариант 2 — embedded (on-disk), без отдельного сервиса: задайте в `.env` путь к каталогу данных:

```bash
QDRANT_PATH=./qdrant_data
```

Если `QDRANT_PATH` задан, используется embedded-режим, а `QDRANT_URL` игнорируется.

## 5. Запуск

UI (Streamlit): загрузите проверяемый документ и источники, нажмите «Проверить».

```bash
streamlit run app.py
```

CLI: печатает таблицу находок и сводку по вердиктам в консоль.

```bash
python -m veridoc.pipeline <документ> --sources <папка_источников>
```

Например:

```bash
python -m veridoc.pipeline report.pdf --sources ./sources
```

Флаг `--sources` необязателен: без него выполняется только проверка внутренней согласованности.

## 6. Оценка

Сначала сгенерируйте датасет, затем посчитайте метрики:

```bash
python eval/seed.py        # генерация датасета (eval/datasets/)
python eval/evaluate.py    # метрики recall/precision/F1/время → eval/results.json
```

`eval/evaluate.py` прогоняет конвейер по датасету и записывает результаты в `eval/results.json`.

## 8. Важные замечания

- **Эмбеддинги — только через `sentence-transformers`, не через `mlx-lm`.** Семейству Qwen3-Embedding нужен именно этот стек; LLM и эмбеддер — разные подсистемы.
- **Запросные эмбеддинги идут с инструкцией.** Запросы кодируются с `prompt_name="query"` (документы — без инструкции). Если модель не зарегистрировала этот prompt, эмбеддер автоматически добавляет ручной префикс `Instruct: ...\nQuery: `.
- **Смена `EMBED_DIM` пересоздаёт коллекцию Qdrant.** При расхождении размерности существующей коллекции с настроенной она удаляется и создаётся заново — переиндексируйте источники.
- **Бюджет памяти ~M4 Max 48 GB.** Индексация источников и верификация документа — разные фазы; держите их раздельно, чтобы не превышать память (LLM и эмбеддер крупные).
- **Фолбэки моделей.** Если штатный `prompt_name="query"` недоступен, используется ручной префикс инструкции (см. выше). Имена модели LLM и эмбеддера задаются через `.env` — при отсутствии конкретного тега замените на доступный совместимый.
- **Воспроизводимость.** Все вызовы LLM — при `temperature=0.0`.

## 9. Метрики оценки

Значения метрик берутся из `eval/results.json` после прогона `python eval/evaluate.py` (см. раздел 6).

| Метрика     | Значение                     |
|-------------|------------------------------|
| Recall      | _из `eval/results.json`_     |
| Precision   | _из `eval/results.json`_     |
| F1          | _из `eval/results.json`_     |
| Время, с    | _из `eval/results.json`_     |

> Плейсхолдеры заполняются после запуска оценки на текущей машине.
